# C3 · 一张地图：把信息组织成能取舍的决策结构

一位创业公司的一号位，某个季度末把自己关进会议室做取舍。桌上不缺材料：大脑里存着全部客户案例，看板上挂着二十多个进行中的项目，每一个都能讲出存在的理由。他要回答的问题只有一个——下季度砍掉哪三个。

两个小时过去，他一个都没砍掉。不是舍不得，是裁不了：每个项目的资料都全，却没有一张图告诉他这些项目共用哪几个能力、哪个能力是胜负手、哪个只是支撑；也没有一个阈值告诉他跌破什么线就该停。他有一屋子的信息，没有一寸决策结构。

后来他换了个做法：不再按项目排列，而是把整个事业拆成能力组件——哪些决定胜负，哪些只是配套，哪些外面买得到，哪些必须自己长。图画完的那个下午，三个该砍的项目自己浮了出来，它们占用的全是可外包的支撑组件，一个控制点都不沾。他后来复盘：以前我缺的不是信息，是把信息变成判断的那张图。

## 地图不是导图，是能取舍的决策结构

很多人以为地图就是思维导图，可思维导图回答「这个主题有哪些分支」，决策地图回答「哪个分支值得走、哪个必须放弃」——发散是导图的美德，却是地图的失职。战略口号也常被当成地图，可「聚焦高端、拥抱 AI」这类句子挂在墙上十年也不会错，正因为永远不会错，它从来没帮你做过任何一次具体的取舍。还有人把信息可视化当成地图，可把数据画成好看的图表，只是把混乱翻译成了漂亮的混乱——可视化解决「看得见」，地图要解决「定得了」，**能看不能裁的图，画得越精美，越像决策的替身**。

最像地图的赝品，是把业务模块画全的那张架构图。它回答「这里有什么」，OS 的地图却要回答「什么最重要、什么是控制点、什么可以外包、什么必须亲手握住」——罗列是地图的原材料，不是地图。而最隐蔽的错属于最勤奋的画图者：目标有了、用户有了、机会有了、因果也画了，唯独没有决策阈值。要素全对，关系缺了最后一环——没有「什么条件下推进、暂停、放弃」的刻度，地图再完整也只是风景，你看得见全局，却依然在每个周一早上凭感觉排优先级。

## 每一代地图，都在朝取舍收窄

决策结构的演化，是「回答的问题」不断收窄的历史。从军事地图到商业战略工具，每一代都比上一代更接近取舍二字：

| 世代 | 工具形态 | 回答的问题 | 离取舍还差什么 |
|---|---|---|---|
| 地形图 | 军事地图 | 这里有什么 | 差「往哪打」 |
| 分析框架 | SWOT / 波特五力 | 局面是什么 | 差「先做什么」 |
| 组合矩阵 | 波士顿矩阵类 | 资源投给谁 | 差「靠什么赢」 |
| 能力组件地图 | CBM 式拆解 | 哪些能力是控制点、哪些是缺口 | 差「何时进退」——由决策阈值补上 |

OS 的一张地图站在这条演化线的末端：它继承 CBM 的精神——把一个人的事业系统拆成可判断、可取舍、可配置、可升级的能力组件——再加上前几代都没有的最后一格，阈值。

这一次还多了一重不同：地图第一次要给机器读。过去的战略图挂在墙上给人看，人脑自带模糊推理，图差一点无妨；现在的地图要喂给系统跑，判断被 AI 在你不在场时执行，模糊就是事故。

| 对照项 | 人读的地图 | 系统读的地图 |
|---|---|---|
| 精度要求 | 大方向对即可 | 变量、因果、阈值必须显式 |
| 更新方式 | 年度务虚会 | 每轮任务回写后校准 |
| 失效形态 | 慢慢过时 | 立刻把错误执行一百遍 |
| 质量判据 | 老板点头 | 能否驱动一次无人值守的取舍 |

实录里有一条正在验证中的闭环把这件事说得很具体：组织大脑自动输出战略地图，识别能力缺口，把缺口变成需求卡交给 AI 开发，结果再写回大脑。地图在这条链上不是汇报材料，是传动件——它的每一格都会被下游当真。

## 六张子图，是从想要到动手的漏斗

六张子图不是并列的六个抽屉，是层层收窄的漏斗，前一张的答案是后一张的前提：

| 子图 | 回答 | 没有它，下一张会怎样 |
|---|---|---|
| 目标地图 | 现在最重要的是什么 | 用户再准也不知为谁服务于什么 |
| 用户地图 | 服务谁、不服务谁 | 机会判断退化为「什么火做什么」 |
| 机会地图 | 母体与势能如何匹配 | 因果分析失去主语 |
| 因果地图 | 关键变量如何互相影响 | 商业设计只剩模仿 |
| 商业地图 | 链路、模式、壁垒在哪里 | 阈值无从设起 |
| 决策阈值 | 什么条件下推进、暂停、放弃 | 前五张全部退回「风景」 |

其中控制点的识别直接调用 [T1 · 非对称优势](../05-threads/T1-非对称优势.md)——决定胜负的组件必须落在别人难以复制的那一格，否则你亲手握住的只是别人也握得住的东西。而整张地图对收敛与秩序的要求，是 [T3 · 信息审美](../05-threads/T3-信息审美.md)在判断层的显形：一张让人一眼看出取舍的图，背后必然是一次残酷的信息收敛。

## 正典：把信息组织成能取舍的结构

把这套结构压成一句正典定义：

> 一张地图，是把文脉和大脑中的信息组织成能判断方向、取舍、优先级和路径的决策结构。

它要回答的第一性问题是：**系统如何知道什么更重要、先做什么、怎么判断？**

拆到可施工的层面，就是六张子图（04d v0.8）：

| ID | 子图 | 内容 |
|---|---|---|
| C3.1 | 目标地图 | 当前最重要目标是什么 |
| C3.2 | 用户地图 | 服务谁、不服务谁、心理账户是什么 |
| C3.3 | 机会地图 | 母体与势能如何匹配 |
| C3.4 | 因果地图 | 关键变量如何互相影响 |
| C3.5 | 商业地图 | 链路、模式、壁垒在哪里 |
| C3.6 | 决策阈值 | 什么条件下推进、暂停、放弃 |

施工图 03a v0.9 在六子图之上又扩了一层，增补能力组件地图与控制点地图，凑成八模块，并给出关键裁决——一张地图 = 战略地图 / 能力组件地图 / 事业系统地图。本仓照 83-术语表口径把两者收进同一个三态框架：六子图是战略地图的骨架，能力组件与控制点两图合成能力组件地图，六子图联动起来跑就是事业系统地图。正典保持六子图不膨胀，八模块作为它的三种用法收纳其下。

一张地图立不立得住，有四道判断标准要过：

| # | 判断标准 |
|---|---|
| 1 | 是否能帮助取舍？ |
| 2 | 是否能解释因果？ |
| 3 | 是否能指导下一步行动？ |
| 4 | 是否能被验证和更新？ |

它的输入是一纸文脉、一个大脑、市场验证记录、创业四关结果、任务复盘与战略目标——B 线的势能地图、壁垒地图在此全部落座；它的输出是一张地图，连同决策地图卡、变量因果图、机会地图、行动阈值与战略路径图。完成标志只有一条：它能让系统知道先做什么、不做什么、哪里是瓶颈、哪里是控制点。达标即进 [C4 · 一条链路](34-C4-一条链路.md)。

本篇为可读性把「地图如何被系统当真」压成了几张对照表，全量的工程答案在[五层架构与六轴评分](36-深潜-五层架构与六轴评分.md)：判断如何被拆进治理层与执行层、健康度如何被六轴量化成一张系统级体检表——六轴评分本质上就是给整个 OS 画的决策阈值。去之前带上一个问题：如果你的系统必须在你休假的一周里独立做出十次取舍，你现在这张图，够它用几次？

## 地图接管你最不清醒的时刻

C3 的判断不停在图上。地图裁决出的优先级、路径与阈值，交给 C4 · 一条链路变成可执行、可验收的行动流程——链路是地图的局部打穿，没有链路，地图只能停在认知层。反向回写同样硬性：每条链路跑完的验证结果回来校准因果地图与决策阈值，被证伪的因果连线必须删除，一张不接受回写的地图，会把第一年的判断执行到第十年。全局关系见[十二模块递归回写图](../50-spine/52-十二模块递归回写图.md)。

要检验这一关过没过，诚实问三件事就够了。第一，你能指着自己的地图，说出最近一次被它否决的项目或机会吗？第二，你能说出自己的事业系统里，哪三个能力组件是控制点、哪几个可以放心外包吗？第三，你每个进行中的项目，都有显式的推进、暂停、放弃条件吗？三问全「是」，进 C4；第 1 问答「否」，你的图是风景不是地图，回到决策阈值补起；第 2 问答「否」，先做能力组件与控制点的拆解，那是取舍的坐标系；第 3 问答「否」，你在用意志力代替阈值，撑得过顺境撑不过换季。完整分诊见[自诊 · 你卡在哪一关](../50-spine/53-自诊-你卡在哪一关.md)。

人真正稀缺的从来不是信息，是取舍——而取舍之所以难，是因为每一次「不做」都在否定一个可能的自己。画这张地图的过程，会逼你把那些含混的「都挺重要」摊开成显式的结构：什么是你的控制点，什么只是你的舍不得；什么在因果链上推动结果，什么只是让你忙起来显得安心。图画完，你会失去一批借口，也会第一次获得那种平静——周一早上不再靠情绪排序，因为该做什么、不该做什么，已经在你状态最好的那天被你自己裁定过了。**地图不是替你做决定，是让你最清醒时刻的判断，接管你所有不清醒的时刻。**
