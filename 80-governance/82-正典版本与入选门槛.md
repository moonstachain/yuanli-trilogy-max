# 正典版本与入选门槛

> 本文回答三个问题：本仓依据哪一版正典（版本冻结）；新内容凭什么进来（入选门槛）；概念要改先改哪里（上游关系与迭代规则）。

## 1. v0.8 正典冻结声明

本仓全部概念叙事，锚定**唯一正典**：

> **soul/extracts/04d-四四四原子级正典体系-v0.8**（十二模块，含每模块的「不是它」字段、第一性问题、原子模块表、判断标准表）。

两条已裁决的命名法附则：

- **C 线命名采 03a-v0.9 四器官法**：C1 一纸文脉 / C2 一个大脑 / C3 一张地图 / C4 一条链路。
- **B1 = 原力借势**。「借势合力」是财富公式（借势 × 合力）的表述，不用作模块名。

冻结的含义：在下一次正典升版裁决之前，本仓任何一篇不得引入与 04d-v0.8 冲突的定义、公式或表行；两张表零删减入库（见[四拍九段](../70-method/71-原力叙事四拍九段.md)第④段规范）；全库术语以[术语表](83-术语表.md)为字面锚。

## 2. 上游关系：车间在 soul，正典层在这里

概念的**修订权不在本仓**。链路是单向的：

> **yuanli-strategy-soul（私有车间）修订 04d → 裁决升版 → 本仓按新版蒸馏重写受影响篇目。**

任何人（包括维护者本人）在写作中发现正典缺陷——定义不自洽、表行有遗漏、模块边界含混——正确动作是**回车间开工**：在 soul 提修订、走车间的裁决流程；裁决通过、正典升版后，本仓才跟进改稿。直接在本仓改概念是最高级别的流程违规，因为它制造了「公开层与车间不一致」的分叉正典。

本仓自有的修订权只覆盖两层：表达层（措辞、切口、纵深素材、金句）与结构层（段位编排、互链、导航）。一句话：**车间管「是什么」，本仓管「怎么讲」。**

## 3. 新内容入选门槛

新篇目入仓前，先过治理五问（蒸馏自 soul/docs/05 的任务启动五问）：

1. **归属**：它属于原力资产、原力创业、原力OS，还是跨三部？——无归属不立项。
2. **服务脊骨**：它服务哪条母公理派生或哪条共享脊骨？——挂不上龙骨的孤篇不收。
3. **输入**：它的源是什么？源的置信度能否支撑🟢，还是必须🟡入库？
4. **输出物**：它落成哪种篇型（模块/深潜/案例/贯穿/脊骨）？验收不以「写完」为准，以「可复用」为准。
5. **回写**：它如何递归回写——⑥段写回哪个模块、金句入不入总表、方法沉淀不沉淀回 70-method？

五问过后，还有三道硬门：

- **格式门**：符合[四拍九段](../70-method/71-原力叙事四拍九段.md)的对应变体模板，frontmatter 契约完整。
- **质量门**：过[八标准与禁区](../70-method/72-叙事质量标准与禁区.md)全检。
- **红线门**：过[内容契约](81-内容契约.md)（蒸馏重写 / 4-gram / PII / 置信度诚实）。

三门是与门（AND）不是或门：任何一门不过即不入库，不设「先上后补」。

## 4. Issue 迭代规则

本仓迭代经 Issue 驱动，规则承接 soul/docs/05：

- **命名前缀**：`[资产]` `[创业]` `[OS]` `[跨三部]` `[治理]` `[知识库]`。无前缀 Issue 视为无归属，先补归属再讨论。
- **优先级**：P0 = 涉及母公理、三部边界、核心公式（此类必须先回车间裁决）；P1 = 影响多篇的共用结构（如九段模板变更）；P2 = 单篇内容问题；P3 = 措辞与格式优化。
- **关闭条件**：以可复用交付物关闭（改稿、模板、术语表条目、验收记录），禁止无输出物关闭。
- **禁止事项**（承接车间铁律）：禁止无归属任务、禁止无回写任务、禁止为了新想法反向污染母公理。

## 5. 三仓关系

| 仓 | 定位 | 侧 | 与本仓关系 |
|---|---|---|---|
| **yuanli-strategy-soul** | 私有车间：源稿、萃取、裁决、治理 | 上游 | 唯一正典所在地；概念修订在此发生 |
| **yuanli-trilogy-narrative** | v1 叙事库：23 篇，四拍七段 | 事业侧 | 前代基线。方法论被本仓升级（七段→九段），v1 保留为历史版本，不再扩写 |
| **yuanli-awakening** | 人生课题公开正典：31 篇原子正典 | 人侧 | 平行姊妹仓，同源于 soul 车间；讲「人如何觉醒」，本仓讲「事业如何长成」 |
| **yuanli-trilogy-max（本仓）** | max 版叙事知识库：55 篇，四拍九段 | 事业侧 | 三部曲叙事的**当前正典层** |

分工一句话：**soul 是车间，awakening 讲人，narrative 是初版，max 是现役**。读者侧的引用与转载以本仓为准；v1 与本仓表述冲突时，以本仓为准；本仓与 04d 正典冲突时，以正典为准并视为本仓 bug（开 `[治理]` Issue 修复）。

## 6. 升版流程摘要

正典从 v0.8 升版时，本仓的跟进流程：

1. 车间发布升版裁决记录 → 本仓开 P0 Issue 登记影响面（哪些篇、哪些表行、哪些术语）。
2. 受影响篇目按新版**蒸馏重写**（不做 diff 式缝补），重过三门。
3. [术语表](83-术语表.md)与本文第 1 节的版本声明同步更新，旧版声明存档于 Issue。
4. 验收记录回填[内容契约](81-内容契约.md)第 7 节。
